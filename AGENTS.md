# DEUS — Istruzioni permanenti

## Fonte di verità

- I requisiti approvati sono quelli documentati nel
  repository corrente.
- La memoria nativa di Codex può fornire contesto,
  ma non sostituisce i documenti del progetto.
- Le decisioni del precedente progetto Deus non
  sono automaticamente valide nel nuovo progetto.

## Autorizzazione dello sviluppo

- Non iniziare lo sviluppo finché GOALS.md non
  contiene obiettivi esplicitamente approvati.
- Non inventare requisiti, architetture o funzionalità.
- Le modifiche documentali richieste esplicitamente
  sono consentite anche prima dell'approvazione.

## Autonomia operativa

- Una volta approvata una milestone, pianifica,
  implementa, testa e correggi autonomamente.
- Continua con le attività autorizzate senza chiedere
  ripetutamente conferma.
- Non dichiarare completate attività non verificate.
- Conserva nei documenti del repository decisioni,
  avanzamento e risultati delle verifiche.

## Limiti

- Non eseguire push, merge, deploy o cancellazioni
  distruttive senza autorizzazione esplicita.
- Non modificare altri repository o progetti.
- Se una decisione essenziale impedisce di proseguire,
  segnala il blocco anziché inventare una soluzione.
